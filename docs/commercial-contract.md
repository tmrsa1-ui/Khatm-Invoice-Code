# عقد فحص تقني — ختم فاتورة (مسودة غير موقَّعة)

هذه مسودة للبائع والمشتري. **ليست عرض سعر نافذًا**، **لا تُنشئ التزامًا تجاريًا**، و**ليست اعتمادًا من هيئة الزكاة والضريبة والجمارك**.

حالة التوقيع: **غير موقَّع**.

## 1. ماهية الخدمة

ختم فاتورة أداة فحص تقني مستقلة لرمز QR (TLV/Base64) وملف XML وفق قواعد محلية منشورة.

الخدمة **ليست**:

- رأيًا نظاميًا أو فتوى امتثال
- اعتمادًا أو شهادة من هيئة الزكاة والضريبة والجمارك
- توليد فاتورة أو توقيعها أو رفعها إلى فاتورة / FATOORA

جملة العقد المعتمدة في كل سطح:

> أداة فحص تقنية مستقلة وليست رأيًا نظاميًا ولا اعتمادًا من هيئة الزكاة والضريبة والجمارك.

`PASS_LOCAL_RULES` يعني اجتياز القواعد المحلية المتاحة في إصدار القواعد المذكور فقط. **ليس** قبولًا لدى فاتورة.

## 2. الطبقات التي تبقى غير حاسمة أو غير مفحوصة

| طبقة | الحالة الافتراضية | متى تتغير |
| --- | --- | --- |
| C14N11 / تجزئة الفاتورة / التوقيع | `INCONCLUSIVE` | فقط بعد تحويل رسمي + fixtures مثبتة |
| XSD / Schematron | `NOT_CHECKED` | بعد ملفات يوفِّرها العميل خارج Git + تطابق sha256 ثم xmllint إن وُجد |
| SDK الرسمي | `NOT_CHECKED` | إذا ثبّته العميل محليًا للمقارنة التفاضلية |

نجاح `xmllint` على مخطط العميل يبقى `NOT_CHECKED` و**ليس اعتماد زاتكا**.
عدم تطابق sha256 لملفات العميل = `FAILED` للسلامة فقط، ليس حكمًا نظاميًا.

الخادم CLI للمخططات المحلية: `--schema-dir` / `--pins` أو `$KHATM_SCHEMA_DIR` / `$KHATM_SCHEMA_PINS`. لا تُوزَّع ملفات الهيئة في Git ولا في المُثبِّت.

## 3. البيانات

النسخة المجانية محلية: لا حساب، لا رفع افتراضي، `connect-src 'none'`.

مسار شبكة لاحقًا فقط بعد موافقة عربية/إنجليزية صريحة، أو تثبيت on-prem بلا رفع خارج شبكة العميل.

لا تُخزَّن أجسام XML/QR في سجلات الدعم.

## 4. تسعير مقصود (ليس فاتورة)

| SKU | السعر | ماذا يُسلَّم | ماذا لا يُسلَّم |
| --- | --- | --- | --- |
| Free local | 0 | PWA / CLI / مصدر iOS | رفع، حساب، لغة اعتماد |
| Team API | يُحدَّد لاحقًا | فحص بعد موافقة، منطقة معالجة معلنة | تحليلات صامتة على بايتات الفاتورة |
| On-premise | يُحدَّد لاحقًا | المحرِّك موقَّع + SBOM | ملفات الهيئة داخل المُثبِّت ما لم يوفِّرها العميل |

التسعير النهائي يحتاج توقيعًا بشريًا. هذه الوثيقة لا تفعِّل فوترة.

## 5. إخلاء

المشتري يبقى مسؤولًا عن التزامه النظامي أمام الهيئة. البائع لا يضمن قبول الفاتورة لدى فاتورة.
